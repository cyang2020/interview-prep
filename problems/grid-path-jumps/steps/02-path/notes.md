# 第二问：输出一条最优路径

## 这一问要做什么

- 写 best_path(board, p, K)：返回一条拿到最大得分的路径，格式 [[行, 列], ...]，第一项是 [0, p]，最后一项在底行。
- 跳过的格子不出现在路径里。多条最优时返回任意一条。

## 核心思路

- 接口加一个 best_path。_fill 多返回一张 parent 表，max_score 改成接收两个返回值，其余不动。
- parent[i][j][k] 存取到 dp[i][j][k] 时用的前驱状态 (pi, pj, pk)；起点和到不了的状态是 None。
- 填表时把 cand > best 那一行从只记 best 改成同时记 who = (pi, pj, pk)，循环结束写进 parent。严格大于才更新，所以打平时留第一个遇到的前驱。
- 回溯：在底行用 max(_bottom_states(dp)) 选出得分最高的 (j, k)，从 (n-1, j, k) 起不断读 parent，直到 None，收集到的坐标反过来就是路径。
- 跳过的格子自然不在路径里：特殊跳的 parent 是 (i-2, j, k-1)，回溯直接从第 i 行退到第 i-2 行。
- 复杂度：填表和第一问一样；回溯最多 n 步；parent 表每个状态一个三元组，是两张表里更占内存的。

## 思考与反问

- 多条最优路径选哪条？按任意一条。_bottom_states 的元组比较在得分打平时选 j、k 更大的，填表时打平留先遇到的前驱，结果是确定的，但不是某种"字典序最小"；要字典序最小得改成 >= 并控制 MOVES 的枚举顺序。
- 为什么存前驱状态三元组而不是走法编号？三元组回溯时直接当下标用，少一次换算；追问内存时可以改成只存 0 到 3 的走法编号，回溯时再按 MOVES 反算。
- 不存 parent 行不行？行：从底行往上反着填一张"从这格到底行还能拿多少"的表，再从起点正着走，每步挑能保持总分的走法。多算一张表、少存 parent，面试里提一句就够。
- 为什么 max_score 不改成"先求路径再求和"？两个函数共用 _fill，各自读底行；绕一圈路径再求和多一层间接，没有收益。
- 底行选出的状态会不会是 NEG？不会：第 0 行到第 n-1 行总能一步一步往下走，至少 k = 0 那一层在每一行都有到得了的格子。

## 测试要点

- test_path_official_examples：三个例子的最优路径都唯一，精确比对。
- test_path_single_row：只有一行时路径只有 [[0, p]]。
- test_path_skips_cell_on_jump：例子 2 的路径只有 3 格，跳过的 [1, 1] 不在里面。
- test_path_is_valid_and_optimal_on_random_boards：150 个随机小棋盘，路径每一步合法、跳数不超 K、得分等于 max_score。

## 更多说明

### 例子 2 的回溯

底行状态里 (3, 2, 1) 得分 255 最高。

| 当前状态 | parent | 收集到的坐标 |
|---|---|---|
| (3, 2, 1) | (2, 1, 1) | [3, 2] |
| (2, 1, 1) | (0, 1, 0) | [3, 2], [2, 1] |
| (0, 1, 0) | None | [3, 2], [2, 1], [0, 1] |

反过来就是 [[0, 1], [2, 1], [3, 2]]。第二行从第 2 行直接退到第 0 行，(1, 1) 从头到尾没出现。

### parent 里存的是什么

每个状态只存一个三元组，不存整条路径。4 行 3 列 kmax = 1 时 24 个状态各存一个，回溯时从终点一个一个往回读。要是每个状态都存从起点到它的整条路径，每个状态要存最多 n 个坐标，内存乘 n。
