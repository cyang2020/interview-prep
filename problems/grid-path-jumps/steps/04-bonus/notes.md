# 第四问：相邻相等加 X、三格递增加 Y

## 这一问要做什么

- 给 max_score 加 X、Y 两个参数：路径里相邻两格值相等每对加 X，相邻三格值严格递增每个窗口加 Y，窗口重叠分别算。
- 相邻按路径顺序算，跳过的格子不参与；跳前跳后两格算相邻。返回加奖励后的最大得分。

## 核心思路

- X 奖励只看当前格和前驱格，填表时在 gain 里直接加，不用新状态。
- Y 奖励要看前驱的前驱，但只需要知道"前驱的值 < 当前值"和"前驱的前驱的值 < 前驱的值"，后者就是前驱那一步是否严格上升，一位就够。
- 状态加一位 c：走进 (i, j) 这一步是否严格上升。dp、parent、count 三张表都多一维，dp[i][j][k][c]。
- 起点 c = 0：没有上一步，从起点走出的第一步拿不到 Y。
- 转移：对每个前驱格算 c = [prev < cur] 和 gain = cur + X·[prev == cur]；再对前驱的两种 pc 各算 cand = dp[pi][pj][pk][pc] + gain + Y·[pc 且 c]，落到 best[c]。
- 一个 (i, j, k) 的两个 c 各自取最大、各自记 parent 和 count，所以 best、who、ways 都变成长度 2 的列表。
- 底行对 j、k、c 全部取最大。best_path 和 count_best_paths 的回溯和求和跟着多一维，逻辑不变。
- X、Y 默认 0，前三问的测试一行不改照样过；X = Y = 0 时两个 c 只是把路线分成两堆，最大值和条数不受影响。
- 复杂度：状态数翻倍，每个状态看 4 个前驱 × 2 个 pc，总共是第一问的 4 倍。

## 思考与反问

- 为什么不把前驱格的坐标放进状态？那样状态是 (i, j, k, 前驱走法)，再往前一格又要一层，状态数乘 4 再乘 4；一位 c 只乘 2。
- 一位真的够吗？Y 的窗口 (a, b, c) 要 a < b 且 b < c；站在 c 处，b < c 当场算，a < b 就是 b 处的 c 位。a 具体是多少不影响以后，所以同 (i, j, k, c) 的路线只留分最高的。
- 奖励改成四格递增怎么办？c 改成"连续上升了几步，封顶 2"，三个取值；窗口长 L 就存 min(连续上升步数, L-1)。
- X 或 Y 是负数怎么办？转移是加法取最大，不依赖正负，代码不改。
- 跳过的格子为什么不参与？题面说跳过的格子不算访问；代码里 prev 取的是 board[pi][pj]，特殊跳时 pi = i - 2，中间那格根本没被读。
- 第二、三问要不要跟着支持奖励？题面只要最大分，但表已经带 c，best_path 和 count_best_paths 加默认参数就顺便支持了，测试里用暴力枚举核对过。

## 测试要点

- test_bonus_official_examples：109、35、255。
- test_pair_bonus_per_adjacent_pair：一列四个 1，三对相邻相等各加一次 X。
- test_triple_bonus_overlapping_windows：1、2、3、4 两个重叠窗口各加一次 Y。
- test_jump_makes_cells_consecutive_for_bonus：跳过 -50 之后，跳前跳后两格相邻能拿 X；跳前、跳后、再下一格递增能拿 Y。
- test_bonus_can_beat_higher_base：不算奖励走 9 那边得 13，算 Y 走 1、2、3 得 106。
- test_bonus_matches_brute_force_on_random_boards：随机小棋盘、随机 X、Y，最大分、路径合法且得分相等、条数三项都和暴力枚举一致。

## 更多说明

### 例子 1 走一遍

board = [[1, 2, 3], [2, 2, 4], [3, 5, 6]]，p = 0，K = 0，X = 10，Y = 100。k 全程是 0，省略。

| 状态 (i, j, c) | 前驱 | 怎么算 | 得分 |
|---|---|---|---|
| (0, 0, 0) | 起点 | 1 | 1 |
| (1, 0, 1) | (0, 0, 0) | 1 + 2，1 < 2 所以 c = 1 | 3 |
| (1, 1, 1) | (0, 0, 0) | 1 + 2 | 3 |
| (2, 0, 1) | (1, 0, 1) 或 (1, 1, 1) | 3 + 3 + Y，pc = 1 且 2 < 3 | 106 |
| (2, 1, 1) | (1, 0, 1) 或 (1, 1, 1) | 3 + 5 + Y | 108 |
| (2, 2, 1) | (1, 1, 1) | 3 + 6 + Y | 109 |

底行最大是 109。(1, 2) 从 (0, 0) 一步到不了，整行表里是 NEG。

### 例子 2 走一遍

board = [[5, 1], [5, 1], [5, 1]]，p = 0，X = 10。

| 状态 (i, j, c) | 怎么算 | 得分 |
|---|---|---|
| (0, 0, 0) | 5 | 5 |
| (1, 0, 0) | 5 + 5 + X，5 == 5 | 20 |
| (1, 1, 0) | 5 + 1 | 6 |
| (2, 0, 0) | 20 + 5 + X | 35 |
| (2, 1, 0) | 20 + 1 | 21 |

两对相邻相等各加一次 X，35。c 全程是 0，因为没有一步严格上升，Y 一次也拿不到。
