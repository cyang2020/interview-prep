# 第三问：数有几条最优路径

## 这一问要做什么

- 写 count_best_paths(board, p, K)：返回拿到最大得分的路径条数。坐标序列不同就算两条。
- 跳过一格和一步一步走过同一格，坐标序列不同，算两条。

## 核心思路

- 接口加一个 count_best_paths。_fill 多返回一张 count 表，起点 count[0][p][0] = 1，到不了的状态是 0。
- count[i][j][k] 回答"有几条路线能以 dp[i][j][k] 这个分走到这个状态"。
- 转移多一个分支：cand > best 时 ways 换成这个前驱的 count；cand == best 时 ways 加上这个前驱的 count。到不了的前驱 count 是 0，加了不影响。
- 答案：底行所有状态里得分等于最大值的，count 相加。不同 (j, k) 的路线坐标序列一定不同，相加不会重复。
- "恰好 k 次"在这一问真正起作用：同一条路线只会出现在一个 k 里。
- 条数用 Python 整数，不取模；最多每行 3 分支，200 行是 3^199 量级，大整数能存。
- 复杂度和第一问一样，多一张整数表。

## 思考与反问

- 要不要取模？按不取，题面没说。要取的话只在两处加：ways 相加时和最后求和时。
- 为什么不是"最多 k 次"的状态？两条路线各跳 1 次，在"最多 1 次"和"最多 2 次"里都算一遍，底行相加会重。恰好 k 次的状态两两不重。
- 为什么打平要加所有前驱，不是取一个？[[0], [0], [0]] K = 1：(2, 0, 0) 来自一步一步走，(2, 0, 1) 来自一跳；两个状态分都是 0，各 1 条，答案 2。漏掉打平分支就只剩 1。
- 第二问的 parent 要不要改？不改，打平时仍留第一个，返回任意一条最优路径就够。
- 条数会不会溢出？[[0, 0]] 重复 30 行、K = 0 就有 2^29 条；用 Java、C++ 要问取模或用 long。

## 测试要点

- test_count_official_examples：例子 1 唯一一条；一列三格全 0 且 K = 1 有 2 条；三列三行全 0 且 K = 0 有 7 条。
- test_count_ties_across_jump_choices：一列五格全 0，K = 0、1、2 分别是 1、4、5 条。
- test_count_only_counts_max_score_paths：分数不同的路线不算进去。
- test_count_matches_brute_force_on_random_boards：值域缩到 -2 到 2 故意制造平局，150 个随机小棋盘和暴力枚举的条数一致。
- test_count_can_exceed_32_bits：30 行两列全 0，K = 0，恰好 2^29 条。

## 更多说明

### 一列五格全 0、K = 2 的 5 条

从第 0 行到第 4 行走 4 行，每步走 1 行或 2 行，最多 2 次走 2 行：

| 走法序列 | 用了几次跳 | 算在哪个状态 |
|---|---|---|
| 1,1,1,1 | 0 | (4, 0, 0) |
| 2,1,1 / 1,2,1 / 1,1,2 | 1 | (4, 0, 1) |
| 2,2 | 2 | (4, 0, 2) |

三个状态得分都是 0，count 分别是 1、3、1，底行相加得 5。K = 1 时 (4, 0, 2) 这层不存在，得 4。

### count 怎么沿着表往下传

(4, 0, 1) 的前驱是 (3, 0, 1) 和 (2, 0, 0)。(3, 0, 1) 的 count 是 2（2,1 和 1,2），(2, 0, 0) 的 count 是 1（1,1），两个前驱得分都是 0，打平相加得 3，正好是 2,1,1 / 1,2,1 / 1,1,2 三条。
