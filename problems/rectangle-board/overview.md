# 整体思路

**一句话。** 只存三样事实——每张矩形的坐标、它的编号、它现在在不在板上，`getAt` 现场算"覆盖这格的最大活跃编号"，于是移除和撤销都退化成翻一个布尔标记。

## 主线：叠放顺序就是编号顺序

"后加的在上面" + "编号按添加顺序递增、永不复用"，两条合起来等于一条不变量：**编号大的一定压着编号小的，任何时刻都成立**。叠放顺序不是一个要维护的状态，它就是编号大小。

把 `getAt` 照这条重写：在所有活跃且覆盖这格的矩形里取编号最大的，没有就 -1。于是第二问那句听着最难的要求——"恢复原始的叠放位置"——不要钱：把标记翻回活跃，它的编号自动决定它压在谁上面。

## 各问的叠加关系

|---|---|---|

| 二 | `history` 栈、`undo` | add / remove 各加一行写历史 |

## 核心不变量

| 不变量 | 为什么成立 | 谁依赖它 |
|---|---|---|
| 编号大 = 压在上面 | 编号按添加顺序发、永不复用 | getAt、undo 恢复位置 |
| `rects` 下标 i = 编号 i+1 | 编号从 1 连续发，矩形对象永不删除 | 按编号找矩形 O(1) |
| 一张矩形最多一条 remove 历史 | 第二次 remove 返回 false 且不记历史 | undo 不会重复复活 |
| 撤销一条 add 时它一定还活跃 | 它之后的 remove 记录压在这条之上，会先被撤销 | undo 不用额外校验 |

## 数据结构

| 结构 | 存什么 | 回答什么问题 | 第几问出现 |
|---|---|---|---|
| `rects` 列表 | 按添加顺序排的 Rect 对象，永不删除 | 按编号取矩形、从上往下遍历 | 一 |
| `Rect.active` | 这张现在在不在板上 | 移除 / 恢复 | 一 |
| `history` 栈 | `("add" 或 "remove", 编号列表)` | 最近一次改动是什么 | 二 |

## 复杂度

| 方法 | 复杂度 | n = 累计添加过的矩形数（≤ 2000） |
|---|---|---|
| addRectangle | O(1) | 只 append |
| removeRectangle | O(1) | 按下标取、翻标记 |
| getAt | O(n) | 从新到旧扫，命中即停 |
| removeAt | O(n) | 一次 getAt |
| batchRemove | O(n) | 扫一遍收集 |
| undo | O(k) | k = 这条记录里的编号个数 |

最坏总代价是查询次数 × 矩形数，受 2000 次调用上限压着，不超过一百万次"点在不在矩形内"的判断。这是**故意**选的线性查询：换来的是 O(1) 的写、O(n) 的内存，和三个追问都不用改数据结构。

## 面试节奏

- 前 3 分钟：先把"编号大 = 在上面"说出来，并问清有没有 bringToFront 这类改层次的操作。这一句决定了后面所有设计。
- 第 3-10 分钟：写第一问。先写 `Rect.covers`，再写三个方法，顺手说清 `getAt` 是线性扫以及为什么够用。
- 第 10-30 分钟：写第二问。先口头列清"哪些算一条历史"，再写 `undo`。历史条目从一开始就写成编号列表。
- 第 30-40 分钟：第三、四问各五分钟。`removeAt` 复用 `removeRectangle`；`batchRemove` 必须自己写历史，因为整批只算一条。
- 最后 10 分钟：写测试。优先这四个：被压住的矩形被移除后 undo、失败的 remove 不占历史、撤销 add 后编号继续递增、`batchRemove` 返回 0 不占历史。

## 常见追问

| 追问 | 一句话答法 |
|---|---|
| getAt 调用量极大怎么办 | 每格挂一个编号列表，添加时往覆盖的每格追加（编号递增所以天然有序），查询从该格列表尾部找第一个活跃的；移除仍只翻标记，列表不用动 |
| 那样的代价 | add 变成 O(面积)、内存 O(总面积)；查询从 O(n) 降到 O(该格深度) |
| 要查询 O(1) | 每格维护只含活跃编号的有序集合，取最大值即答案；代价是 add / remove 都变成 O(面积 · log 深度) |
| 加 redo | 再开一个栈：undo 时把记录压进 redo 栈，任何新的 add / remove 清空 redo 栈 |
| 加 bringToFront | "编号 = 叠放顺序"就不成立了，要另开一个只增的层次序号，getAt 比层次序号而不是比编号 |
| 问某张矩形现在露出多少格 | 遍历它覆盖的每格做一次 getAt，O(面积 · n)；要常用就改成每格维护活跃集合 |
| 板子变成 10^9 × 10^9 | 坐标不再能按格存，只能按矩形存——正好是本解法；per-cell 的方案直接失效 |
