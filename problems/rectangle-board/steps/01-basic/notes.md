# 第1问：贴、撕、查

## 面试官给的骨架

```
RectangleBoard(int width, int height)
int     addRectangle(int x1, int y1, int x2, int y2)
boolean removeRectangle(int rectangleId)
int     getAt(int x, int y)
```

## 思路

### 开口先定的口径

- 有没有"把某张挪到最上面"的操作？**没有**。这决定了编号大小就是叠放顺序，不需要单独存层次。
- 移除是整张移除，还是只擦掉它在某格上的覆盖？**整张**。这决定了每张矩形的状态只有"在板上 / 不在板上"两种，不需要按格记部分覆盖。
- 编号会不会复用？**不会，而且连续递增**。这决定了列表下标可以直接当编号表，省掉一个字典。
- 查询坐标会不会越界？**不会**。这决定了 `getAt` 里不写边界检查。
- 规模多大？最多 2000 次调用、板子最大 50×50。这决定了 `getAt` 线性扫就够，不用建索引。

### 只存事实，不存推导结果

事实是每张矩形的 `x1, y1, x2, y2`、它的编号 `rid`、它的 `active`。推导结果是"每格现在最上面是谁"。

很多人第一反应是开一个 50×50 的二维表，贴的时候把编号刷进去，查的时候直接读。这条路在 `removeRectangle` 上就断了：撕掉上面那张之后，被它压住的要重新露出来，但二维表里只留了最上面是谁，下面压着谁已经被刷掉了。要恢复只能把所有活跃矩形按编号从小到大重刷一遍，O(矩形数 × 面积)。能跑，但每个追问都要重刷一次，代码还多。

所以存矩形，不存格子。`rects` 是一个按添加顺序排的列表，矩形**永远不从里面删除**——`removeRectangle` 只把 `active` 改成 False。两个理由：编号永不复用，所以坐标得留着；第二问的 undo 要把它原样放回来。

### 三个方法各一行逻辑

| 方法 | 做什么 | 为什么能这么简单 |
|---|---|---|
| addRectangle | 编号 = 列表长度 + 1，append | 编号连续递增这条口径 |
| removeRectangle | 下标取出来，翻 `active` | 整张移除这条口径 |
| getAt | 从列表尾往前找第一个 `active` 且覆盖这格的 | 编号大 = 在上面这条不变量 |

`getAt` 从后往前扫是整问的关键：列表尾部是编号最大的，也就是最上面的，第一个命中的就是答案，不用比较也不用排序。

### 用题目的例子走一遍

4 列 3 行。`addRectangle(1,0,2,1)` 发到编号 1，`addRectangle(2,1,3,2)` 发到编号 2。此时 `rects = [Rect1(活), Rect2(活)]`。

| 调用 | 从后往前扫到的第一个命中 | 返回 |
|---|---|---|
| getAt(2,1) | Rect2 活跃且 x∈[2,3]、y∈[1,2] 包含 (2,1) | 2 |
| removeRectangle(2) | Rect2 活跃 → 翻成不活 | true |
| getAt(2,1) | Rect2 不活跃跳过，Rect1 的 x∈[1,2]、y∈[0,1] 包含 (2,1) | 1 |
| getAt(3,2) | Rect2 不活跃跳过，Rect1 的 x∈[1,2] 不含 3 | -1 |
| removeRectangle(2) | Rect2 已经不活跃 | false |

### 复杂度

add 和 remove 都是 O(1)。`getAt` 是 O(n)，n 是累计添加过的矩形数，最多 2000。最坏总代价出现在一半调用是 add、一半是 getAt 的时候：1000 × 1000 = 一百万次坐标比较，毫秒级。内存 O(n)。

## 常见疑问

### 为什么"最上面"等于"编号最大"

题目两句话绑在一起：同一格上后加的盖在先加的上面；编号按添加顺序从 1 递增且永不复用。所以编号 5 一定比编号 3 后加，一定压着编号 3。中间把 4 撕掉也不影响 5 和 3 的相对关系。

拿三张铺满整块板的矩形看：

| 操作 | 活跃的编号 | getAt(1,1) |
|---|---|---|
| 加 1、2、3 | 1,2,3 | 3 |
| 撕掉 3 | 1,2 | 2 |
| 撕掉 1 | 2 | 2（画面不变，但 1 确实不在了） |
| 撕掉 2 | 无 | -1 |

每一行的答案都是"活跃集合里的最大编号"，不需要任何额外记录。

### 已经撕掉的矩形为什么不从列表里删掉

删了会坏两件事。一是编号永不复用，`addRectangle` 用"列表长度 + 1"算新编号就不对了，得另存一个计数器。二是第二问的 `undo` 要把撕掉的那张原样放回来，坐标必须还在。留着它、只翻 `active`，代价是扫的时候多走几个不活跃的元素——n 上限 2000，不值得为这个省。

### `covers` 为什么是两边都带等号

题面写了 including every cell on its boundaries：`(x1,y1)` 是左上角那个单元格本身，`(x2,y2)` 是右下角那个单元格本身，两头都算。所以 `(1,1)-(3,3)` 覆盖 x = 1,2,3 和 y = 1,2,3，一共 9 格，不是 4 格。写成 `x1 <= x <= x2 and y1 <= y <= y2`。一边漏等号，单格矩形 `(0,0)-(0,0)` 就永远查不到。
