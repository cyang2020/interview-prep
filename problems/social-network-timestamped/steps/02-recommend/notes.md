# 第二问：2-hop 推荐，带时间

## 面试官给的骨架

题面只给了规则，没给签名：A → B → C，A → B → D，A → M → C，给 A 推荐 [C, D]，C 排前面，因为有两个中间人；并列按最近优先；电话面版本会要 top-K。按规则还原成一个方法，t 和 k 从一开始就收下。

```python
class FollowGraph:
    # 第一问的 update / check 不变

    def recommend(self, a, t, k=None):
        """t 时刻给 a 推荐"a 关注的人也在关注的人"，按中间人数排序，返回前 k 个。"""
        pass
```

## 思路

**开口先定的口径。**

1. 两步都只走 t 时刻存在的关注关系。这决定了第二问必须先有 following_at(a, t)，而不是直接读某个"当前关注集合"。
2. 剔除两类候选：a 自己，以及 a 在 t 时刻已经关注的人。这决定了第一层要整体先取出来存着，剔除时查它。
3. 并列按"指向候选人的最新一条关注边的时刻"从新到旧排。另一种口径是按 a → 中间人那条边的时刻。先说选哪种。这决定了 following_at 返回的是"被关注者 → 这段关注开始的时刻"，不是集合。
4. 再并列按名字排，只为结果确定、测试好写。面试里说"剩下顺序任意"即可。
5. k 为 None 返回全部。

**新增的三个方法。**

- _PairHistory.followed_since(t)：t 时刻处于关注状态就返回这段关注开始的时刻，否则 None。处于关注状态时，不超过 t 的最后一条事件一定是那次"开始关注"，所以答案就是二分查找找到的那条事件的时刻。
- FollowGraph.following_at(a, t)：遍历 _history[a] 的所有键，这是 a 关注过的所有人，含已取消的；每个调 followed_since(t)，不是 None 的留下。返回 {被关注者: 开始时刻}。不这么做（没有两层 map）的话，要扫全部 (a, b) 对才能找出 a 开头的，代价和整个系统的关系数成正比。
- FollowGraph.recommend(a, t, k)：三个动作。先取 first_hop = following_at(a, t)。再对 first_hop 里每个 b 取 following_at(b, t)，每个 c 在 count 里加一，在 latest 里记指向 c 的最新边时刻；c 等于 a 或 c 在 first_hop 里就跳过。最后按 (-count, -latest, 名字) 排序，取前 k。

**为什么剔除要在每次遇到时判断，不是只判一次。** a 自己和已关注的人可能被多个中间人指到。只在第一次遇到时判断，第二次遇到还是会被计数。所以判断写在内层循环里。

**用带时间的例子走一遍。**

| 时刻 | 事件 |
|---|---|
| 1 | A 关注 B |
| 2 | A 关注 M |
| 3 | B 关注 C |
| 4 | B 关注 D |
| 5 | M 关注 C |
| 6 | B 关注 A |
| 7 | M 关注 B |
| 8 | A 关注 D |
| 9 | B 取消关注 C |

| 查询 | first_hop | 第二层遇到的人 | 剔除 | count / latest | 结果 |
|---|---|---|---|---|---|
| recommend(A, 5) | {B, M} | B→C, B→D, M→C | 无 | C: 2 / 5；D: 1 / 4 | [C, D] |
| recommend(A, 7) | {B, M} | B→C, B→D, B→A, M→C, M→B | A 是自己，B 已关注 | C: 2 / 5；D: 1 / 4 | [C, D] |
| recommend(A, 8) | {B, M, D} | 同上，D 关注的人没有 | A、B，加上 D 已关注 | C: 2 / 5 | [C] |
| recommend(A, 9) | {B, M, D} | B→D, B→A, M→C, M→B | A、B、D | C: 1 / 5 | [C] |
| recommend(A, 2) | {B, M} | 无 | 无 | 空 | [] |

**复杂度。** 第一层 F 个人，每个中间人关注过 G 个人，每个关系一次二分查找：F × G × log(历史长度)。排序 C log C，C 是候选数。k 小而 C 大时可以换成大小为 k 的堆，C log k。内存是 count 和 latest 两张表，O(C)。

## 常见疑问

### 为什么 following_at 要遍历"关注过的所有人"而不只是"现在关注的人"

_history[a] 的键里包含已经取消关注的人，因为历史不删。查 t 时刻关注谁，必须逐个判断，不能跳过任何一个：A 第 1 秒关注 B、第 5 秒取消、第 9 秒再关注，查 following_at(A, 10) 时 B 要在里面，查 following_at(A, 7) 时不在。只看"现在"的集合会把两种查询答成一样的。

### "最近"为什么取指向候选人的边，不取 A 出去的边

A 第 1 秒关注 B、第 2 秒关注 M，B 第 3 秒关注 X，M 第 4 秒关注 Y。X 和 Y 都只有一个中间人。按指向候选人的边：Y 的边是第 4 秒，X 的是第 3 秒，Y 排前。按 A 出去的边：到 Y 经过 M，M 是第 2 秒，到 X 经过 B，B 是第 1 秒，也是 Y 排前。这个例子两种口径结果相同，但一般情况下会不同，所以要先说清。选指向候选人的边，理由是它更能反映"这个人最近被你的朋友关注了"。

### 一个大 V 中间人关注了一百万人怎么办

following_at(大 V, t) 要扫一百万条历史，每次推荐都这么扫跑不动。三种答法：每个中间人只取最近关注的 N 个人；推荐结果离线算好存起来，查询时直接读；对中间人的关注列表抽样。面试里说出第一种就够，后两种是追问备用。
