# 整体思路

**一句话。** 每对人存一个按时间排好的变化列表，查任意时刻靠二分；推荐是在"t 时刻关注谁"这个列举上做两层计数。

**各问是叠加关系。** 第一问定下两层 map（关注者 → 被关注者 → 历史）。第二问不改第一问任何东西，只加 followed_since、following_at、recommend 三个方法；两层 map 的外层就是为第二问的列举准备的。

## 全部状态转移

| 当前状态 | 触发 | 条件 | 下一状态 |
|---|---|---|---|
| 未关注 | update(A, B, t) | A ≠ B | 从 t 起关注 |
| 关注 | update(A, B, t, following=False) | | 从 t 起未关注 |
| 任意 | update(A, A, t) | | 不变 |
| 任意 | check | | 不变，只读 |
| 任意 | recommend | | 不变，只读 |

## 数据结构

| 结构 | 存什么 | 回答什么问题 | 第几问出现 |
|---|---|---|---|
| _history，两层 map | 关注者 → 被关注者 → _PairHistory | 这一对人的历史在哪；A 关注过谁 | 1 |
| _PairHistory.times | 变化时刻，升序 | 二分找不超过 t 的最后一次变化 | 1 |
| _PairHistory.states | 每次变化后是否关注 | 那次变化后的状态 | 1 |
| recommend 里的 count | 候选 → 中间人数 | 排序主键 | 2 |
| recommend 里的 latest | 候选 → 指向他的最新边时刻 | 并列排序 | 2 |

## 面试节奏

- 前 3 分钟：确认 update 是否按序、有没有取消、闭区间、并列规则。说"这是有向图，边带时间，我按关注者分层存每对人的历史"。
- 10 分钟：写 _PairHistory 和 update/check。写完先跑"关注、取消、再关注"那条测试。
- 10 分钟：写 following_at 和 recommend。先跑题面例子。
- 留 5 分钟：补时间边界和剔除的测试，讲状态变化。
- 剩余：追问。

## 常见追问

| 追问 | 答法 |
|---|---|
| update 乱序到达 | record 已经按位置插入，check 不变 |
| 取消关注 | following=False，历史列表照记 |
| 大 V 中间人关注上百万人 | 每个中间人只取最近 N 个，或离线预计算 |
| 历史无限增长 | 旧事件归档，或只保留最近 N 条加一个基准状态 |
| 并发 | 写加锁；历史只追加不改，读旧时刻不用锁 |
| 和快照版的关系 | 快照就是一个时刻；边带起止时间就是本题的做法 |
| 时间线合并（设计 Twitter） | K 个关注者的发帖流用堆合并取最新 N 条 |
