# 整体思路

**一句话。** 反馈慢一拍，所以每次新交的数只能押在"在等结果的那个数"的一侧：押中那一侧这次没白花，押错那一侧白扔一手。最少次数的策略就是让白扔的那一侧小、不白扔的那一侧大，分割比例按 A[k] = 1 + A[k-1] + A[k-2] 这张表来；多局版是每局各跑一遍同样的策略，批次数等于最慢那一局。

**三问是叠加关系。** 第一问只管正确和合规：候选区间加一个在等结果的数 pending，结果到了就收缩区间。第二问换掉选数规则：不取中点，按 A 表的比例切。第三问不改选数规则，把循环拆成 propose（算出这批交什么）和 absorb（收上一批的结果）两个动作，让多局并排跑。

## 全部状态转移

单局的状态是三样东西：候选区间 lo..hi、在等结果的数 pending、剩余预算 k。每一次调用就是一条转移，k 减 1。

| 当前情况 | 这次交什么 | 拿到的结果 | 下一情况 |
|---|---|---|---|
| lo == hi | 不调，直接返回 | | 结束 |
| pending 不在区间里或没有 | lo + min(hi - lo, A[k-1]) | 没信息，丢掉 | pending 在区间里 |
| pending 在区间里 | 放进下方块：lo + min(a - 1, A[k-1]) | CORRECT | 返回 pending |
| pending 在区间里 | 同上 | pending 偏大 | 区间缩到下方块，新数还在里面 |
| pending 在区间里 | 同上 | pending 偏小 | 区间缩到上方块，新数在外面，pending 置空 |
| pending 在区间里 | 放进上方块（下方块兜不住时） | 三种 | 对称 |

放下方块的条件是：下方 a ≤ A[k] 且上方 b ≤ A[k-1]，否则放上方块。多局版每一局各自走这张表，已定的局交 -1 且不走表。

## 数据结构

| 结构 | 存什么 | 回答什么问题 | 第几问出现 |
|---|---|---|---|
| lo, hi | 候选区间两端 | 答案还可能是哪些数 | 一 |
| pending | 上一次交的、结果没回来的数 | 下一条结果在说谁 | 一 |
| A（列表） | A[k] = k 次调用最多搞定多少候选 | 这一刀切在哪 | 二 |
| k | 剩余预算 | 查 A 表用哪一项 | 二 |
| _Game（每局一个） | 上面四样加 sent、answer | 这局这批交什么、定了没 | 三 |

## 面试节奏

- 前 2 分钟，口头定口径：最少次数按最坏情况；猜测必须落在范围内，所以没有"打空枪"；信息够了就返回，不等确认。
- 第一问 5 分钟：写候选区间加 pending 的循环，说清"返回值说的是 pending 不是这次交的数"，以及 lo 用 max 的原因。
- 第二问 15 分钟：先讲"新数只能押一侧"，推出 A[k] = 1 + A[k-1] + A[k-2]，报出 1e9 要 43 次；再改选数规则。要主动说"攒两个数再三分"为什么更慢。
- 第三问 10 分钟：先说批次数等于最慢那一局、各局帮不上忙；再把循环拆成 propose 和 absorb，讲 -1 和提前返回。
- 测试：n ≤ 300 的每个 secret 跑一遍，裁判检查越界和重复；第二问实测最坏次数要正好等于 A 表；第三问例 1 的三批。

## 常见追问

| 追问 | 答法 |
|---|---|
| 为什么不能先交两个数再三分 | 第二个数的结果要到第三次调用才到，第三次必须交一个新数而新区间还不知道，这一手必废。3 次换 3 倍是每次 1.44 倍，Fibonacci 的 1.618 更快 |
| 允许猜范围外或重复的数会不会更快 | 不会。这种数的结果是已知的，等于两边都白扔。规则只是堵掉偷懒的写法，不改下界 |
| 怎么证明 43 是下界 | 递推式里每一项都是被迫的：新数只落一侧，落到的一侧少 1 次、另一侧少 2 次。n ≤ 11 用不设前提的博弈树搜索验证过，和公式逐个相等 |
| 按平均次数最优呢 | 同一个分叉结构，目标换成按候选数加权的期望，用动态规划求；最坏最优的切法不一定期望最优 |
| 反馈延迟 d 拍怎么办 | 同一个推法：定义"还剩 k 次、在等结果的数都没用时能覆盖多少"，按新数落在哪一侧写递推。延迟 1 拍得到 1 + A[k-1] + A[k-2]，延迟更长要重新推，不要现场背公式 |
| 多局时快的局能不能帮慢的局 | 不能。局 i 的结果只说局 i，猜测范围也各管各的；最大 upperBound 那一局单独拿出来就要那么多次 |
| 每批只能交 m 个数怎么办 | 变成每批挑哪些局推进。剩余次数最多的局优先，不然它拖尾 |
| 第三问的猜测总数是不是也最少 | 是。一局的猜测数等于它处于未完成状态的批次数，就是它自己的次数，第二问已经压到最少 |
| A 表多大 | 1e9 只要 44 项（A[0] 到 A[43]），A[k] = 2 乘 Fib(k+1) 减 1 |
