# 第一问：四邻居同步传播，多源 BFS

## 面试官给的骨架

题面只有签名，没有函数体，下面按签名还原。输入只有 0 和 1，返回全部感染的天数。

```python
def time_to_full_infection(grid: list[list[int]]) -> int:
    pass
```

完整实现另有 _infection_days(grid, D=None, K=1) 和 _full_infection_days(grid, infection_day)。前者计算日期，后者检查是否全部感染。D、K 从第一步就收下，当前公开接口只用默认值，之后增加恢复和阈值时不改这个调用方式。

## 思路

**开口先定的口径。**

1. 只认上下左右，不认对角线。DIRECTIONS 只有四项，否则中心感染的 3×3 会错误地返回 1。
2. 第 0 天是输入，今天新感染最早明天传播。队列里处理第 t 天的坐标，只给新位置写 t+1，不能沿同一行一直写 t。
3. 允许多个来源，它们都在第 0 天入队。只放第一个来源，会错过其他来源更近的路径。
4. 必须全部健康格感染才算完成。没有来源但还有健康格返回 -1，不能因为队列为空就返回 0。
5. 本实现不改 grid，单独存 infection_day。数组里的日期会继续用于恢复和死亡判定，不是单纯为避免修改而复制原网格。

**先看一行 [[1, 0, 0]]。** 测试程序把这三格交给 time_to_full_infection。_infection_days 初始化得到 [[0, -1, -1]]，queue 只有 (0, 0)。弹出它时，右边首次感染日是 1；弹出 (0, 1) 时，最右首次感染日是 2。最后 _full_infection_days 看到两个原本健康的位置都已有日期，返回最大值 2。

| 操作 | queue | infection_day |
|---|---|---|
| 第 0 天来源入队 | [(0, 0)] | [[0, -1, -1]] |
| 处理感染日 0 的 (0, 0) | [(0, 1)] | [[0, 1, -1]] |
| 处理感染日 1 的 (0, 1) | [(0, 2)] | [[0, 1, 2]] |
| 处理感染日 2 的 (0, 2) | [] | [[0, 1, 2]] |

**两个结构各存一件事。** infection_day[row][col] 存首次感染日期，-1 表示没有被发现。queue 存等待处理首次传播的坐标。它不存康复时间，不存所有仍感染的格子，也不重复保存日期；弹出坐标后从 infection_day 读取日期。

处理相邻的 (r, c) 要同时满足边界有效、原始 grid[r][c] 是 0、infection_day[r][c] 仍是 -1。满足时先写日期，再入队。不检查日期，两个来源就可能把同一个位置重复入队；等到出队才写日期也会出现这个问题。

**为什么 FIFO 顺序对应天数。** FIFO 是先加入的先取出。全部第 0 天来源先入队，它们追加的第 1 天位置排在后面；第 1 天追加的第 2 天又排在后面。因而先处理完较早日期，再处理较晚日期。这就是多源 BFS，多个来源一起按距离逐层处理。

**正确性。** 一个位置首次被第 t 天感染的邻居发现，存在一条 t+1 步的传播路径。如果存在更短路径，之前的队列层就该发现它，与首次发现矛盾。因此记录的是最早感染日。所有健康格的最晚日期就是完成日；仍有 -1 则不可达。

**复杂度。** 设 V=R×C。每个格子最多入队一次，每次检查四个邻居，计算日期 O(V)，检查完成条件 O(V)，总时间 O(V)，额外空间 O(V)。最坏要读完输入才能区分全感染与某个未检查位置仍健康，所以时间下界也是 Ω(V)。

## 常见疑问

### queue 里存的是所有仍感染的细胞吗

不是。测试程序只要求首次感染的日期，求解器只需让每个感染位置尝试传播一次。以 [[1, 0, 0]] 为例，处理完 (0, 0) 后，它已经不在 queue 中，但题面里它仍然感染，并没有恢复。

| 时刻 | queue | 题意中已感染的位置 |
|---|---|---|
| 输入 | [(0, 0)] | (0, 0) |
| 第一次传播后 | [(0, 1)] | (0, 0)、(0, 1) |
| 第二次传播后 | [(0, 2)] | 三个位置 |

如果把 queue 当成所有仍感染的位置，就会误以为出队等于恢复。出队只表示它对首次感染日期的贡献已经处理完。

### 为什么写了日期不算同一天立刻传播

写 infection_day 只是确定未来的感染日。真正处理这个新位置的邻居，要等它自己的队列项出队。用 [[1, 0, 1]] 看两个来源：

| 操作 | 中间日期 | queue |
|---|---|---|
| 初始化 | -1 | [(0, 0), (0, 2)] |
| 处理左来源 | 1 | [(0, 2), (0, 1)] |
| 处理右来源 | 1 | [(0, 1)] |
| 处理中间 | 1 | [] |

右来源看到中间已经有日期，不会再加入一份。中间始终排在两个第 0 天来源之后，没有在第 0 天继续传播。

### 为什么既看 grid 又看 infection_day

grid 是测试程序给的初始类型，infection_day 是求解器新增的日期。前者回答“原来能不能感染”，后者回答“是否已经安排感染”。例如初始 [[1, 0, 0]]：

| 位置 | 初始 grid | 最终 infection_day | 含义 |
|---|---|---|---|
| (0, 0) | 1 | 0 | 初始来源 |
| (0, 1) | 0 | 1 | 第一天感染 |
| (0, 2) | 0 | 2 | 第二天感染 |

只看 grid 会重复访问已经算过的健康位置；只看日期则不知道未访问位置是不是后续会加入的免疫格。两个判断分别对应两个信息。
