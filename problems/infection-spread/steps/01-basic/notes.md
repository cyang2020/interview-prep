# 第一问：四邻居同步传播，多源 BFS

## 这一问要做什么

- 写 time_to_full_infection(grid)：网格只有 0 健康、1 感染，每天感染格把上下左右的健康格传染，今天刚被传染的明天才往外传。
- 返回所有健康格都被传染完要几天；有健康格永远传不到返回 -1，没有健康格返回 0。

## 核心思路

- 接口 time_to_full_infection(grid) 返回所有健康格感染完的天数。内部拆成两段：_infection_days(grid, D=None, K=1) 算每格的感染日期，_full_infection_days(grid, infection_day) 检查是否全部感染。D、K 第一问先收下不用，后面加恢复和阈值不改调用方式。
- 两个数据结构：infection_day[row][col] 存每格首次感染的日期，-1 表示没被感染到；queue 存等着做第一次传播的 (row, col)。
- 初始化：grid 里所有 1 写 infection_day=0 并全部入队，多个来源都从第 0 天开始。
- 传播：弹出 (row, col)，看四个邻居 (r, c)，满足"在边界内、grid[r][c] 是 0、infection_day[r][c] 还是 -1"就写 infection_day[row][col]+1 并入队。日期在入队时写，两个来源不会把同一格排两次。
- queue 先进先出：第 0 天的全部弹完才轮到第 1 天的，所以写进去的日期就是最早感染日。多个来源同时起步的 BFS，就是多源 BFS。
- _full_infection_days 只看 grid 是 0 的格子：有一个 infection_day 还是 -1 就返回 -1，否则返回最大日期。
- 复杂度：每格最多入队一次、每次看四个邻居，时间 O(RC)，额外空间 O(RC)。

## 思考与反问

- 相邻是四邻居还是八邻居？按四邻居，DIRECTIONS 只放四个偏移。八邻居的话 3×3 中心感染答案是 1 不是 2。
- 没有感染源但有健康格返回什么？按 -1，由 _full_infection_days 判。不能看 queue 空了就返回 0：[[0, 0]] 要返回 -1，[[]] 和 [[1]] 才返回 0。
- 要不要直接改 grid？不改，另开 infection_day。这张日期表第三、四问要拿来算恢复日和死亡标记，不只是为了不污染输入。
- 为什么日期在入队时写、不在出队时写：[[1, 0, 1]] 两个来源都挨着中间格，出队时才写会把中间格入队两次。
- 追问"queue 里是不是所有仍在感染的格子"：不是。一格做完第一次传播就出队，题意里它还在感染，只是对别人的感染日已经没有新贡献。
- 追问"为什么不每天扫一遍全图"：每天扫是 O(天数 × RC)，[[1, 0, 0, 0, 0]] 要扫 4 遍；queue 每格只碰一次。

## 测试要点

- test_empty_grid_and_single_cell：[]、[[]]、[[1]] 返回 0，[[0]] 返回 -1。
- test_no_source_cannot_start：2×2 全健康没有来源，返回 -1。
- test_new_infection_waits_until_next_day：一行 5 格返回 4，今天新感染的格子明天才传播。
- test_only_four_neighbors_spread：3×3 中心来源返回 2，对角不算邻居。
- test_all_sources_start_on_day_zero：两个角各一个来源的 3×3 返回 2，两个来源同时开始。
- test_single_column_uses_row_bounds：一列 3 格返回 2，行列下标不能写反。
- test_dates_do_not_overwrite_input：调用后 grid 原样不动，再调一次答案一样。

## 更多说明

### [[1, 0, 0]] 每一步长什么样

| 操作 | queue | infection_day |
|---|---|---|
| 第 0 天来源入队 | [(0, 0)] | [[0, -1, -1]] |
| 弹出 (0, 0)，日期 0 | [(0, 1)] | [[0, 1, -1]] |
| 弹出 (0, 1)，日期 1 | [(0, 2)] | [[0, 1, 2]] |
| 弹出 (0, 2)，日期 2 | [] | [[0, 1, 2]] |

最后 _full_infection_days 看两个原本是 0 的格子都有日期，取最大值 2。

### [[1, 0, 1]] 两个来源为什么不会重复入队

| 操作 | 中间格 infection_day | queue |
|---|---|---|
| 初始化 | -1 | [(0, 0), (0, 2)] |
| 弹出左来源 | 1 | [(0, 2), (0, 1)] |
| 弹出右来源 | 1，已有日期，跳过 | [(0, 1)] |
| 弹出中间格 | 1 | [] |

中间格排在两个第 0 天来源后面，不会在第 0 天就继续往外传。

### 为什么既看 grid 又看 infection_day

grid 回答"这格原来能不能被感染"，infection_day 回答"是否已经安排了感染日"。只看 grid 会重复处理已经算过的健康格；只看 infection_day 分不清 -1 是"还没传到"还是第二问里"永远不会感染的免疫格"。
