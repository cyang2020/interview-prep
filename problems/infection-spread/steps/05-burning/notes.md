
solution.py 保留前四问的所有函数。minimum_deaths 调 min_deaths_daily_fast；其他入口对应独立变种，不需要把同一套规则重新写一遍。

| 入口 | 对应规则 | 返回值 |
|---|---|---|
| min_deaths_one_burn | 初始化前最多或恰好一次 | 最小人数、行列 |
| best_initial_burn | 同上，支持另一种倒计时模型 | Choice |
| best_timed_burn | 初始化后任选一天一次 | Choice |
| best_daily_burn | 每日决策、计费和次数等组合 | 最小人数 |

Choice 的字段是 deaths、action、day。Burn 的字段是 axis、index，例如 Burn('col', 1)。model 使用 FixedLifetime；若题目明确改成有限 N 天的 T/K 倒计时，再使用 Countdown。

## 思路

**开口先定的口径。**

1. 烧一整行或一整列，包括健康、感染和免疫格；已经死亡的格子不重复计费。少算健康格，会让策略看起来无代价。
2. 主线先烧，再处理到期，再同步传播。第 1 天的动作发生在第 0 天标记确定之后，不能因为烧掉邻居而重算已有标记。
3. 主线每天可选择不烧，直到没有感染后结束。省略不烧这个候选，会把本来零死亡的局面强迫烧死人。
4. 允许重复选择已烧空的线。无限次数时它是合法的零代价动作；禁止重复会改变状态和证明。
5. 主线统计最终全部死亡。只计病死或者只看前 N 天，要用保留计时器的 best_daily_burn，不能提前把所有必死细胞收费。
6. 每个网格状态都是不可变的 tuple，候选分支生成自己的下一状态。不同动作必须从同一个当前局面出发，否则先试的动作会污染后试的结果。

**先看单次版，复用第四问就够。** 初始化前只烧一次时，有 R+C 条候选线。对每条线复制输入，把线上还活着的格子变成 3，记录 burn_deaths；再调用 time_to_end_with_deaths 得到 natural_deaths。两者加已有死亡就是这一候选的实际总数。allow_no_burn=True 再增加完全不烧的候选。

例如 grid=[[1, 0, 1, 0, 1]]、D=2、K=2，不烧会让第 1、3 列都在感染时接触两个来源，病死 2 个。开始前烧第 2 列，付出 1 个死亡，两边剩下的来源各自传播，新感染只接触一个来源，最终死 1 个。

| 候选 | 焚烧死亡 | 后续病死 | 总数 |
|---|---|---|---|
| 不烧 | 0 | 2 | 2 |
| 烧第 2 列 | 1 | 0 | 1 |
| 烧整行 | 5 | 0 | 5 |

**为什么单次版保证最小。** 任意合法方案就是一个允许的动作。算法对每个动作准确算出总费用，再取最小值。真正的最优动作一定在枚举集合里，所以算法不会比最优值更大；返回值又来自一个合法动作，所以不可能比最优值更小。两个方向合起来就是相等。

**任选一天只烧一次。** 第一次动作前没有干预，所以所有候选共用同一条无干预前缀。best_timed_burn 每天试全部行列，然后用 deaths_without_burn 计算动作后的剩余死亡。已有感染保留 remaining 和 will_die，不能把当前 grid 重新初始化成全新的第 0 天。

在固定寿命模型中，一整天没有新感染后，未来邻居数只会减少，烧也不会增加来源；后续不会再有新感染。此时所有死亡标记固定，推迟烧同一条线不能减少最终全部死亡，免费烧时提前做也至少不差，所以无期限版本可以停止枚举日期。K=1 且计入最终全部死亡时，后续感染全是必死，越早阻断同一条线只会减少线外感染，只需第一天。K≥2 不能用这个结论，因为同时到达的邻居数也影响死亡。

**再看每日主线 [[0, 1, 0, 0, 1]]，D=2，K=1。** 测试程序只给初始网格，求解器需要决定动作。第 1 天烧第 1 列，右来源感染第 3 列；第 2 天烧第 3 列，阻止它继续感染第 2 列。最终死 2 个。

| 日期 | 动作 | 题意中的日末状态 | 累计实际死亡 |
|---|---|---|---|
| 0 | 无 | [0, 1, 0, 0, 1] | 0 |
| 1 | 烧第 1 列 | [0, 3, 0, 1, 1] | 1 |
| 2 | 烧第 3 列 | [0, 3, 0, 3, 2] | 2 |

只烧一次的最少结果是 3。第二天的选择确实能改善结果，因此不能选完第一条线后就假设再也不干预。

**完整 state 存什么。** FixedLifetime 用 Cell(status, remaining, will_die) 描述每格。status 是 0、1、2、3；remaining 是距到期还有几天；will_die 是已经固定的死亡标记。best_daily_burn 的缓存键还包括 burns_left、days_left、still_must_burn，分别记录剩余次数、剩余期限和是否还欠一次必须的动作。没有限制的字段是 None。

这些字段足以计算所有未来转移。同样的网格但剩余次数不同，不是同一个问题；同样的感染但剩余时间不同，也可能在下一次烧之前先到期。过去已经死了多少不放入缓存，solve 只返回未来还要增加多少，过去费用由调用者相加。

**递推只有一个选择。** 对每一个合法动作，准确求出当天新增死亡和下一状态，然后取最小值。DP 在这里指缓存每个状态的最优未来结果。

```
F(state) = min(本次新增死亡 + F(下一状态))
```

结束后未来费用是 0。若结束时仍欠规定必须完成的一次焚烧，该分支不可行，返回 inf。至少一次要配合 budget=1 才是恰好一次；只设置 require_one_burn=True 不限制总次数。

**最优性证明。** 假设所有更接近结束的状态已经返回真正的最优值。任意合法完整策略都有一个首动作。固定首动作后，它的后半段不可能比下一状态的最优值更小。反过来，先做该动作，再接上下一状态的最优策略，正好能达到这个和。枚举全部合法首动作取最小值，就得到当前状态的真正最优值。结束状态提供归纳起点，缓存只避免重复计算，不删候选。

**为什么归纳不会碰到无限循环。** 有 horizon 时，每一步 days_left 减一。无期限的固定寿命模型可用 P=(D+1)×健康格数+全部感染 remaining 之和：旧感染每天减少剩余时间；每个新感染从健康项扣 D+1、增加 D，净减少一；烧健康或感染也只会减少 P。只要日程还没结束，一天过后 P 严格下降，因此递归必然终止。

**代码里的剪枝为什么安全。** 不再烧的结果是一个确实可执行的上界；如果每天必须烧但已有全死的线，可以重复选它达到同一结果。已经标记会死、并会在期限内到期的细胞，无论等病死还是提前烧死都至少贡献一，是全部死亡计费时的下界。只统计病死时这个下界改成 0。如果本次费用加后继下界已不小于已知可行结果，该分支不可能更优，可以跳过。上界等于下界时可以直接返回。到达完全相同的完整后继状态时，只保留更小的本次费用也不会漏掉更优方案。

**主线还能减少状态。** D≥2 时，每个感染只需要第一次有效传播。它完成这次传播后不再有健康邻居，之后多久恢复不再影响新感染。又因为标记为必死的细胞无论病死还是烧死都计一，可以在标记产生时先记账，之后烧到它不再加一。

min_deaths_daily_fast 使用五个真实常量。它们是内部编码，不是传入 grid 的 0、1、2、3 编码。

| 常量 | 仍需首次传播 | 尚未记账的死亡 |
|---|---|---|
| HEALTHY_CELL | 否 | 烧时计一 |
| SPREAD_SAFE | 是 | 烧时计一 |
| SPREAD_DOOMED | 是 | 已计一 |
| SAFE_CELL | 否 | 烧时计一 |
| DEATH_COUNTED | 否 | 已计一 |

SPREAD_SAFE 传播后变 SAFE_CELL，SPREAD_DOOMED 传播后变 DEATH_COUNTED。后两种状态可能包含现实中还没到期的旧感染；这不是提前改变题意，因为旧感染已经没有健康邻居，最终死亡费用也已准确记下。

**简化为什么仍然最优。** 对任意动作序列，忽略旧感染剩余寿命不会改变新感染；提前记必死费用不会改变最终收费，每格还是最终死亡才贡献一。健康、待传播、是否最终收费的信息足以区分所有影响未来的情况。没有待传播位置后，未来不会新感染，所有病死已记账，继续烧也不可能减费。因此原过程与五状态过程对每个策略给出的最终费用相同，应用同一个 DP 证明即可得到原题最优值。D=1 没有传播，代码直接处理初始标记与第一天是否强制烧。

**每天必须烧。** 无限次数并允许重复选择时，第一次烧完就有一条全死线。以后想不干预时重复烧它，费用和效果都是零。所以五状态版本只额外强制第一次动作。有限次数且每天强制消耗次数时，等待会消耗预算，必须用保留 burns_left 的完整版本。

**其他变种怎么调用。**

| 设置或模型 | 改变的条件 | 保留的信息 |
|---|---|---|
| count_burned=False | 只统计病死 | remaining、will_die |
| burn_before=False | 先完成到期与传播，再烧 | 完整日内顺序 |
| budget=B | 最多 B 次 | burns_left |
| budget=1、require_one_burn=True | 恰好一次 | 次数、必须动作标记 |
| horizon=N | 只算最多 N 天内死亡 | days_left、remaining |
| Countdown、horizon=N | T/K 触发倒计时的另一套规则 | 完整计时与有限期限 |

Countdown 用当天开始的快照。尚未死亡且没有倒计时的细胞，邻居数达到 K 开始死亡倒计时，达到 T 但不到 K 开始恢复倒计时；新计时当天不减，已有计时当天减一。默认恢复后还能再次进入计时，permanent_immunity=True 才禁止。初始感染没有自动附上 D 天期限，T=0 甚至可以没有来源就触发。因此必须给 horizon，不能使用一次感染的 BFS 结论。有限期限始终递减，完整 DP 的归纳证明仍成立。

FixedLifetime 在没有感染时结束，horizon 是额外上限。Countdown 按给定期限结束。先传播后烧的设置要完成当天两个环节后才检查结束。只有尚未结束且仍有次数时，allow_no_burn=False 才要求动作。输入默认不含死格；若传入 3，就把它视为已经计入目标的死亡常数。

**复杂度。** 设 V=RC，B=R+C+1。开始前单次 O(BV)，任选日期单次 O(HBV)，固定寿命无期限版 H≤V。每日固定寿命搜索若展开 S 个状态，时间 O(SBV)，缓存 O(SV)，递归层上的候选还需要 O(HBV) 工作空间。五状态版最多 5^V 个网格状态，最坏仍指数级。Countdown 的无后续干预评估需要 O(NV)，其搜索可给出 O(S(B+N)V) 的保守上界。这些是时间上界，最小死亡人数的证明不等于时间复杂度最优的证明。Python 递归实现面向小网格，过长路径还可能触及递归深度限制。

## 常见疑问

### 既然一个格子只感染一次，为什么还要搜索

测试程序给的是初始 grid，不会提前给求解器一套焚烧动作。固定动作后，每格确实只感染一次；但不同动作会改变之后哪些格子能感染、何时感染。求解器仍然要在这些合法策略中选一个。

| [[0, 1, 0, 0, 1]]，D=2、K=1 | 动作限制 | 最小死亡 |
|---|---|---|
| 完全不烧 | 无动作 | 3 |
| 任选一天烧一次 | 一次 | 3 |
| 第一天烧第 1 列，第二天烧第 3 列 | 两次 | 2 |

这个例子还可以手工证明下界 2：第一天不烧会新增三个必死格；烧整行直接死五个；烧任意一列先死一个，而且至少还剩一个来源能感染一个健康邻居，K=1 使它也必死。任何策略至少死两个，已有策略达到两个，所以两个是最优值。一般输入由递推证明覆盖。

### 同样烧一列，为什么初始化前和第一天的答案不同

测试程序给 [[1, 1]]、D=1、K=1。区别在于求解器何时计算初始标记。先烧再初始化时，剩余来源已经没有感染邻居；先初始化时，两个标记已经固定。

| 顺序 | 烧后剩余来源的标记 | 焚烧死亡 | 病死 | 总数 |
|---|---|---|---|---|
| 先烧，再初始化 | 假 | 1 | 0 | 1 |
| 第 0 天初始化，第 1 天烧 | 真 | 1 | 1 | 2 |

best_timed_burn 必须从当前 state 做 model.burn，不能烧完后再调用 model.initial。后者会把正确的第二行误算成第一行。

### 已经说是必死，为什么又能烧它来改善答案

在最终全部死亡目标里，这个细胞自己贡献的一不会变，改善来自阻断它下一次传播。求解器烧掉的是还没完成首次传播的 SPREAD_DOOMED；它本身费用已经记过，后面少感染其他位置才产生收益。

| 动作 | 被烧格自己的最终费用 | 对后续传播的作用 |
|---|---|---|
| 放任它传播后病死 | 1 | 邻居可能新增必死 |
| 首次传播前烧掉 | 1 | 不再感染邻居 |
| 已完成传播后再烧 | 1 | 无新增传播可阻断 |

只计病死的版本又不同，提前烧能避免这个格子自己的病死费用，因此必须保留计时器，不能直接使用 SPREAD_DOOMED 的提前记账。

### state 为什么需要剩余时间，只有 grid 不够吗

调用者提供的初始格子值只描述感染与否，搜索到中途还要知道哪天到期。D=2、K=2，一行当前是 [1, 0, 1]，中间健康；左右两个感染都已有不会死的标记。

| 左右来源的 remaining | 下一天先到期 | 中间会否感染 | 中间未来死亡 |
|---|---|---|---|
| 都是 1 | 两个都到期 | 否 | 0 |
| 都是 2 | 都不变成免疫 | 是 | 1 |

相同的 grid 数值，未来费用不同，所以完整搜索必须把 remaining 放入键。五状态简化能够不存它，是因为它同时重新定义了待传播状态和死亡计费，证明了两种过程等价，不是直接把字段删掉。

### 通过很多测试就能说死亡人数最小吗

不能。测试程序只能比较运行过的输入，求解器对所有合法输入的保证来自证明。这里每一层保证各自解决一件事。

| 保证 | 需要成立的条件 | 得到的结论 |
|---|---|---|
| 状态完整 | 剩余时间、次数、期限齐全 | 同键的未来相同 |
| 转移准确 | 同时更新、固定标记、只收费一次 | 每个方案费用准确 |
| 动作完整 | 每条行列及允许的不烧 | 最优策略在候选中 |
| 递推归纳 | 步骤终止、后继最优 | 当前结果全局最优 |
| 剪枝安全 | 可行上界、有效下界 | 不丢更优分支 |
| 对照测试 | 独立逐日模拟和无剪枝搜索 | 检查实现错误 |

完整实现的 tests.py 包含一个独立的逐日无剪枝搜索，与缓存和五状态版本比较。它帮助发现写错的分支，但不会取代前面的数学论证，也不会证明指数级搜索已经是最快算法。
