# 第三问：D 天恢复，最后感染日加 D

## 面试官给的骨架

下面按签名还原。本问的返回值从“全部感染”变成“没有仍感染的细胞”，前两问接口保留。

```python
def time_to_stable_state(grid: list[list[int]], D: int) -> int:
    pass
```

_infection_days 已经接收 D，本问只在首次传播前增加 D=1 的处理。time_to_stable_state 从日期数组取最后一个感染日，再加 D。

## 思路

**开口先定的口径。**

1. 第 t 天感染，在第 t+D 天开始时结束感染，且先恢复再传播。代码必须单独处理 D=1，不然会把来不及传播的初始来源扩散出去。
2. 恢复后永久免疫，不会重新变成健康。一个位置最多感染一次，infection_day 才能只写一次。
3. 感染仍只需要一个感染邻居。这保证来源第一次有效传播就处理完所有可感染邻居，多邻居阈值不在本问范围内。
4. 稳定是没有感染，不要求所有健康位置都曾感染。不能调用 _full_infection_days 把不可达健康格当成错误。
5. 时间是题目中的整数天数，不是实际墙上时钟。测试直接给 D，不调用系统时钟，也不使用 sleep。

**用 [[1, 0, 0]]、D=2 走一遍。** 测试程序希望知道最后一次恢复发生在哪一天。左格第 0 天感染，在第 2 天恢复；它第 1 天仍能感染中间。中间第 1 天感染，在第 3 天恢复，第 2 天仍能感染右格。

| 天数 | 先处理到期 | 当天新增感染 | 题意中的日末状态 |
|---|---|---|---|
| 0 | 无 | (0, 0) 初始来源 | [1, 0, 0] |
| 1 | 无 | (0, 1) | [1, 1, 0] |
| 2 | (0, 0) 恢复 | (0, 2) | [2, 1, 1] |
| 3 | (0, 1) 恢复 | 无 | [2, 2, 1] |
| 4 | (0, 2) 恢复 | 无 | [2, 2, 2] |

首次感染日仍然是 [0, 1, 2]，和第二问的 BFS 一样。求解器算出最晚日期 2，再加 D=2，得到 4。表中是按规则真实演化的状态，solution.py 并不每天构造这些整张网格。

**为什么恢复没有改变首次感染日。** D≥2 时，一个第 t 天感染的格子在第 t+1 天一定还具有传染性。它会感染全部仍健康的邻居。以后这些邻居不会重新健康，所以它再存活几天也不会产生新的首次感染。queue 只需保留每个位置的这一次有效传播。

沿一条长度 d 的最短路径，来源第 0 天感染，后续位置依次在第 1 到第 d 天感染，每个前驱都至少活到第一次传播。另一方面，感染一天最多跨一条边，不可能比最短距离更早。这两个方向证明 BFS 日期就是实际首次感染日。

**为什么结束时间是最大日期加 D。** 每个感染恰在 infection_day+D 到期。取这些到期日的最大值，就是最后一个感染消失的时刻。没有感染时 last_infection_day=-1，直接返回 0。D=1 时辅助函数只记录初始来源，不进入传播循环，最大日期只能为 0 或 -1。

**复杂度。** 日期计算和取最大值都是 O(RC)，额外空间 O(RC)，不随 D 的大小增加。D=1000000 的同一行仍然直接返回 1000002。最坏需要检查是否存在来源，存在 Ω(RC) 下界，时间最优。

## 常见疑问

### queue 里的旧位置为什么不用一直留到恢复

测试程序要的是结束日，求解器已经知道一个第 t 天感染的位置会在 t+D 到期，不必每天保存它“还没恢复”这个重复事实。以 D=2 的一行为例：

| 已处理的感染日期 | queue 中待传播位置 | 已知最晚到期日 |
|---|---|---|
| 初始化 | (0, 0) | 2 |
| 0 | (0, 1) | 3 |
| 1 | (0, 2) | 4 |
| 2 | 无 | 4 |

queue 空表示没有新的首次传播要处理，不表示真实时刻已经来到第 4 天。返回值直接取已知的最后到期日，所以不用把旧位置反复加回去。

### D=1 为什么不能先感染邻居再恢复

题面先到期再传播。测试程序给 [[1, 0]]、D=1 时，初始来源在第 1 天开始时已经免疫。

| 天数 | 传播前状态 | 新感染 | 日末状态 |
|---|---|---|---|
| 0 | [1, 0] | 初始来源 | [1, 0] |
| 1 | [2, 0] | 无 | [2, 0] |

如果先传播再恢复，右格会在第 1 天感染，结束时间变成 2，那是另一套时序。代码在初始化之后、第一次 while queue 之前返回，正是为了实现当前口径。

### 为什么之前返回 -1，这一问却返回一个天数

调用者问的问题变了。第一、二问问健康格是否全部感染；第三问问有没有感染还没结束。求解器不能共用不同的停止条件。

| 输入 | 全部感染的答案 | D=2 稳定的答案 |
|---|---|---|
| [[0]] | -1 | 0 |
| [[1]] | 0 | 2 |
| [[1, 2, 0]] | -1 | 2 |

最后一个例子的右格永远健康，但左来源第二天恢复后，全图已经没有感染，因此第三问返回 2。
