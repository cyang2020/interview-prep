# 第二问：免疫细胞作为永久阻挡

## 面试官给的骨架

题面没有完整实现，下面按签名还原。输入新增 2，仍然返回所有健康格感染需要的天数。

```python
def time_to_full_infection_with_immunity(grid: list[list[int]]) -> int:
    pass
```

完整文件保留第一问全部函数，追加这个入口。它直接复用 time_to_full_infection，因为已有的传播条件只进入 0。

## 思路

**开口先定的口径。**

1. 免疫用 2 编码，永久有效。_infection_days 不把它作为来源，也不进入它，否则 [[1, 2, 0]] 会错误地连通。
2. 只有 0 需要感染。_full_infection_days 只检查原本健康的位置，否则全免疫输入会错误地返回 -1。
3. 只要一个健康位置永远无法感染，就返回 -1。不能仅报告已到达部分花了几天。
4. 传播可以绕行，不能只看来源与目标之间那一条直线。queue 仍然检查四个方向。

**用绕行例子看发生了什么。** 测试程序给 [[1, 2, 0], [0, 2, 0], [0, 0, 0]]，左上是来源，中间上方两格免疫。求解器不能从 (0, 0) 直接向右跨过 (0, 1)，但可以沿最下方绕到右上。

| 感染日 | 新感染位置 | 必须经过的前一个位置 |
|---|---|---|
| 0 | (0, 0) | 初始来源 |
| 1 | (1, 0) | (0, 0) |
| 2 | (2, 0) | (1, 0) |
| 3 | (2, 1) | (2, 0) |
| 4 | (2, 2) | (2, 1) |
| 5 | (1, 2) | (2, 2) |
| 6 | (0, 2) | (1, 2) |

最后所有健康格都有日期，返回 6。两个免疫格在 infection_day 中保持 -1，但 _full_infection_days 不要求它们有日期。

**为什么核心循环不用改。** 初始来源检查 grid[row][col]==1，发现邻居检查 grid[r][c]==0，完成检查也只针对 0。这三个条件已经把免疫从来源、传播目标和待完成集合里排除。增加一个清楚表达题意的入口就够了，复制一份循环会让两份边界或日期逻辑逐渐不一致。

**正确性。** 把免疫格和它连接的边从网格图中删除。剩下的仍然是每条边传播一天的图，多源 BFS 算出的日期仍是最短距离。不可达的健康位置留为 -1，判定失败；没有健康位置时返回 0。

**复杂度。** 时间 O(RC)，额外空间 O(RC)。第一问是本问完全没有免疫格的特例，读取输入的最坏时间下界仍然成立。

## 常见疑问

### 感染源旁边有免疫，整个网格就不可能感染了吗

不是。免疫只阻止经过该位置，其他方向仍然可走。测试程序给同样一个来源，求解器要看所有合法路径，不能遇到 2 就结束整个搜索。

| 输入 | 日期或结果 | 原因 |
|---|---|---|
| [[1, 2, 0]] | -1 | 健康格与来源隔开 |
| [[1, 2], [0, 0]] | 2 | 下方路径可达 |
| [[1, 0, 2, 0, 1]] | 1 | 两侧各有来源 |

只有队列处理完后仍有健康格不可达，才返回 -1。

### 没有感染源为什么有时返回 0，有时返回 -1

第二问要求全部健康格感染。测试程序给 [[2, 2]] 时没有任何必须感染的位置，任务从第 0 天已经完成；给 [[0, 2]] 时有一个健康位置，却没有来源。

| 输入 | 健康位置数 | 返回值 |
|---|---|---|
| [] | 0 | 0 |
| [[2, 2]] | 0 | 0 |
| [[0, 2]] | 1 | -1 |

不能只用“queue 是不是空”决定答案。_full_infection_days 还要检查 grid 中原本为 0 的位置。

### 免疫格的 infection_day 是 -1，会不会和未感染的健康格混淆

日期数组只负责日期，格子原来的类型仍在 grid 中。求解器同时看两者就能区分。以 [[1, 2, 0]] 为例：

| 位置 | grid | infection_day | 是否需要感染 |
|---|---|---|---|
| (0, 0) | 1 | 0 | 初始已感染 |
| (0, 1) | 2 | -1 | 否 |
| (0, 2) | 0 | -1 | 是 |

真正导致返回 -1 的是最后一格，而不是中间的免疫格。这样不需要再加一个标记数组。
