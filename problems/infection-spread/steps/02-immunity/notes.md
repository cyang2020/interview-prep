# 第二问：免疫格 2 不感染也不传播

## 这一问要做什么

- 写 time_to_full_infection_with_immunity(grid)：网格里多了 2，2 永远不被传染、也不往外传，传播要绕着它走。
- 返回值同第一问：全部健康格传染完的天数，有传不到的返回 -1，没有健康格返回 0。

## 核心思路

- 新接口 time_to_full_infection_with_immunity(grid)，输入多了 2。代码里它直接返回 time_to_full_infection(grid)，一行。
- 为什么传播循环一行不用改：来源只收 grid==1，传播目标只收 grid==0，_full_infection_days 只检查 grid==0。这三个条件已经把 2 排除在来源、传播目标、待完成三个集合之外。
- 2 在 infection_day 里一直是 -1，但 _full_infection_days 不看它，不会误报 -1。真正让答案变 -1 的是"grid 是 0 且 infection_day 是 -1"的格子。
- 传播可以绕过免疫格：[[1, 2, 0], [0, 2, 0], [0, 0, 0]] 右上角沿底部绕过去要走 6 步，返回 6。
- 复杂度不变，时间和额外空间都是 O(RC)。

## 思考与反问

- 免疫用 2、-1 还是字母编码？按 2。整道题 0 健康、1 感染、2 免疫、3 死亡，一个数字一个含义，后面几问不换。
- 有一个健康格永远够不到，返回 -1 还是返回已感染部分的天数？按 -1。[[1, 2, 0]] 返回 -1。
- 没有健康格时返回什么？按 0。[[2, 2]] 和 [[1, 2]] 都是 0，[[0, 2]] 是 -1，所以不能用"queue 空了没"决定答案，必须数 grid 里的 0。
- 为什么不另写一份循环处理 2：两份循环的边界和日期逻辑以后会改得不一致，第三、四问还要在这一个循环上继续加规则。
- 追问"来源旁边就是 2，整张图是不是就不可能感染了"：不是，2 只封它自己那一格。[[1, 2], [0, 0]] 从下面绕过去，返回 2。

## 测试要点

- test_immune_wall_blocks_a_healthy_cell：[[1, 2, 0]] 返回 -1，不能穿过 2。
- test_spread_can_go_around_a_wall：3×3 两个免疫格挡在中间，沿底部绕行返回 6。
- test_immune_cells_do_not_need_infection：[[2, 2]]、[[1, 2]] 返回 0，免疫格不算待感染的格子。
- test_sources_on_both_sides_of_a_wall：[[1, 0, 2, 0, 1]] 两侧各有来源，返回 1。

## 更多说明

### 绕行例子每天感染谁

| 感染日 | 新感染位置 | 从哪传来 |
|---|---|---|
| 0 | (0, 0) | 初始来源 |
| 1 | (1, 0) | (0, 0) |
| 2 | (2, 0) | (1, 0) |
| 3 | (2, 1) | (2, 0) |
| 4 | (2, 2) | (2, 1) |
| 5 | (1, 2) | (2, 2) |
| 6 | (0, 2) | (1, 2) |

### 两种 -1 怎么区分

以 [[1, 2, 0]] 为例，infection_day 里中间和右边都是 -1，要靠 grid 分开：

| 位置 | grid | infection_day | 要不要感染 |
|---|---|---|---|
| (0, 0) | 1 | 0 | 初始已感染 |
| (0, 1) | 2 | -1 | 不要 |
| (0, 2) | 0 | -1 | 要，所以答案 -1 |
