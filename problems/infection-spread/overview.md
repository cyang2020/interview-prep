# 整体思路

**一句话。** 用 infection_day 记每个位置首次感染的日期，queue 只处理一次有效传播；第四问按分支增加 infected_neighbors 或死亡判定，第五问在这些确定的转移外面枚举动作或缓存 state 的最小未来死亡。

**各问的叠加关系。** 前三问复用同一段日期计算，第二问把 2 排除，第三问处理 D=1 并把最后感染日加 D。第四问有两个分支：永久感染的阈值版累计邻居数，固定死亡版仍按普通感染日期判定死亡。第五问沿用固定死亡版，不默认把感染阈值也一起提高。

每步 solution.py 都保留之前的接口和方法顺序。_infection_days 从第一步就接收 D=None、K=1，前两问只使用默认值，后面直接沿用参数位置。新的题面函数逐步追加，旧测试一并保留。

## 核心不变量

| 字段或状态 | 变化 | 始终成立的条件 | 生效阶段 |
|---|---|---|---|
| infection_day | -1 到某个非负日期 | 首次入队时赋值一次 | 一至四 |
| queue | 追加、弹出坐标 | 日期非递减、每格最多入队一次 | 一至四 |
| grid 中的 2 | 无变化 | 不能感染、不能传播 | 二起 |
| D=1 | 第 1 天到期 | 首次传播之前结束感染 | 三、死亡版 |
| infected_neighbors | 出队邻居贡献加一 | 只用于永久感染阈值版 | 四 |
| will_die | 感染时固定 | 不随邻居后来恢复而改变 | 四、五 |
| state 中的 remaining | 每天减一 | 到期先于当天传播 | 五主线 |
| state 中的死亡格 | 保持死亡 | 焚烧与病死不重复计费 | 五 |
| solve 的返回值 | 当前状态的最小未来费用 | 不包含过去已付的死亡 | 五 |

第一、二、四问的“全部感染”由 _full_infection_days 检查，存在健康且 infection_day=-1 就返回 -1。第三、死亡版的结束条件不同，不调用这段检查，最后一个感染到期即可。

## 数据结构

| 结构 | 存什么 | 回答什么问题 | 第几问出现 |
|---|---|---|---|
| DIRECTIONS | 四个坐标偏移 | 哪些位置相邻 | 一 |
| infection_day | 每格首次感染日，-1 未感染 | 这个位置哪天感染 | 一 |
| queue | 等待首次传播的 (row, col) | 下一次处理哪个感染日期 | 一 |
| infected_neighbors | 尚未感染格的已处理感染邻居数 | 是否已经有 K 个不同邻居 | 四阈值版 |
| infected_neighbor_count | 一个格子前一日邻居的数量 | 刚感染时是否达到死亡阈值 | 四死亡版 |
| Cell | status、remaining、will_die | 当前细胞如何继续演化 | 五 |
| model.neighbors、model.lines | 格子编号的邻接与行列 | 传播和烧要碰哪些位置 | 五 |
| state | 全部 Cell 的不可变元组 | 是否到达过同一未来局面 | 五 |
| cache | 状态到最小未来死亡 | 相同局面是否需要再求一次 | 五 |

infection_day 不是原网格的副本，里面是日期而不是 0、1、2 的状态。queue 也不是所有仍感染的细胞名单，完成第一次有效传播的坐标会出队，但该细胞可能还没恢复。

## 为什么可以复用 BFS

BFS 是按离来源的距离从小到大处理顶点的队列算法。一条邻接传播需要一天，所以距离正好对应感染日期。多个来源同时从第 0 天入队，就是多源 BFS。

看一行 [[1, 0, 0]]，D=2。第 0 天左格感染；第 1 天中间感染；第 2 天左格先恢复，中间仍可感染右格；第 4 天最后的右格恢复。恢复没有改变 0、1、2 这三个首次感染日，因为每个感染都至少拥有下一天的一次传播机会。

这个推理要求传播阈值为 1、恢复后永久免疫，并且 D≥2。D=1 单独处理。阈值和恢复同时存在、恢复后会重新变健康、感染期间可能提前死亡时，不能直接套这个结论。

## 最小死亡人数与运行时间最优是两件事

前四问的明确版本是 O(RC)，最坏必须读完整个输入，因此达到了时间下界。第五问开始前一次枚举 R+C 个动作，任选一天一次再枚举日期；每日决策用 DP，也就是缓存每个状态的最优未来答案。

第五问证明的是最小死亡人数。证明要先保证状态足够描述未来，再保证所有合法首动作都被比较，再保证转移计费准确。安全剪枝必须有可行上界和不能低于的下界，不能凭“这一行感染多”就排除别的策略。

每日决策的最坏运行时间仍然是指数级。五状态版本省掉计时器，适用于固定死亡标记、最终全部死亡计费的主线，不代表已经证明这个问题没有更快算法。对应 notes.md 给出递推、终止性、剪枝和状态简化的证明。

## 60 分钟面试节奏

- 前 5 分钟确定四邻居、返回值、免疫编码、恢复顺序。先手算 [[1, 0, 0]] 和 [[1, 2, 0]]，把第 0 天、第 1 天写清楚。
- 第 5 到 20 分钟写第一、二问：所有来源入队、首次发现时记录日期、最后检查不可达健康格。测试空网格、无来源、中心来源、免疫墙。
- 第 20 到 32 分钟做第三问：先测 D=1，再解释 D≥2 的一次传播机会，最后感染日加 D。用仍有健康格却已经稳定的例子检查停止条件。
- 第 32 到 45 分钟按面试官给的第四问分支写：阈值版加计数，死亡版用前一日邻居判定。测试同日新感染不能互相贡献邻居。
- 第 45 到 55 分钟说明第五问动作、时序和计费。单次版枚举；每日版先写完整状态递推，确认最优子结构后再考虑简化。
- 最后 5 分钟测先烧后判标记和判标记后烧的差别，再测单次最少 3、两次能做到 2 的例子。把复杂度和适用条件一起说出来。

## 常见追问

| 追问 | 一句话答法 |
|---|---|
| 为什么不用 DFS | 首次感染日对应最短距离，BFS 按距离出队 |
| 为什么不用每一天扫描全图 | 固定传播只需每格一次，重复扫描增加一个天数因子 |
| queue 是所有仍感染的格子吗 | 不是，只含尚未处理首次传播的坐标 |
| 只有感染一次为什么还要 DP | 固定一套动作才确定传播，不同动作序列仍需比较 |
| 感染阈值和死亡阈值都是 K 吗 | 两个独立分支，含义分别写在接口里 |
| 感染会恢复，计数还能只加吗 | 不能，第四问阈值版限定永久感染 |
| 第五问能提前记必死人数吗 | 只有最终焚烧与病死都计费且标记固定时成立 |
| 每天必须烧比可不烧难多少 | 可重复空线且次数无限时，只额外强制第一次 |
| 只统计 N 天内的死亡呢 | 保留剩余时间与剩余天数，不能提前收未来死亡费用 |
| 网格很大呢 | 固定传播用队列；每日精确搜索仍需约束决策规模 |
| 测试全过就是最优证明吗 | 不是，测试验实现，候选覆盖和递推证明验最优性 |
