# 第三问：快照上的 recommend(user_id, k)

## 面试官给的骨架

```python
class Snapshot:
    def recommend(self, user_id: str, k: int) -> list[str]: ...
        # 2-hop 推荐：数 user_id 关注的人里有几个关注了每个候选人；
        # 剔除 user_id 自己和已关注的人；按数量从多到少取前 k
```

## 思路

**开口先定的口径。**

1. 候选是"user_id 关注的人关注的人"，两层，不往第三层走。
2. 剔除 user_id 自己和 user_id 已关注的人。这决定了第一层要整体存着，内层循环每次遇到都查一次。
3. 并列按名字排，只为结果确定。这个版本没有时间戳，没有"最近"可用；面试里说"并列任意"也行。
4. k 为 0 返回空，k 超过候选数返回全部。

**三步。** 取 first_hop = _following[user_id]。对 first_hop 里每个 b，遍历 _following[b] 里每个 c：c 等于 user_id 或 c 在 first_hop 里就跳过，否则 count[c] 加一。按 (-count, 名字) 排序，切前 k。

**为什么剔除写在内层循环。** 自己和已关注的人可能被多个中间人指到。只在第一次遇到时判断，第二次遇到还是会计数。

**为什么 _following[b] 不用 get。** b 来自 first_hop，first_hop 是表里的值，而 follow 写入前检查过 followee 存在，所以 b 一定是表里的键。用方括号是在说明你知道这个保证。

**用题面例子走一遍。** A 关注 B、C；B 关注 D、E；C 关注 D、F。

| 步骤 | 看谁的那一行 | 遇到谁 | 剔除 | count |
|---|---|---|---|---|
| 0 | first_hop = {B, C} | | | 空 |
| 1 | B:{D, E} | D、E | 无 | D:1 E:1 |
| 2 | C:{D, F} | D、F | 无 | D:2 E:1 F:1 |
| 3 | 排序 | | | D、E、F |

recommend(A, 2) 切前 2 是 [D, E]。

再加两条边看剔除：B 关注 A，C 关注 B。看 B 那行多出 A，是自己，跳过。看 C 那行多出 B，在 first_hop 里，跳过。结果不变。

**复杂度。** 计数 F × G，F 是第一层人数，G 是每个中间人的关注数。排序 C log C，C 是候选数。k 小、C 大时换成大小为 k 的堆，C log k；Python 里 heapq.nsmallest(k, count, key=...) 或 Counter.most_common(k)。内存 O(C)。

## 常见疑问

### 和版本一的推荐差在哪

算法一样。版本一每取一层都要按 t 过滤，并列按最近的边排。这个版本表里只有当前状态，直接取行，没有时间可比，并列按名字或任意。

### 大 V 中间人怎么办

A 关注了一个关注一百万人的账号，第二层就要扫一百万。答法和版本一相同：每个中间人只取前 N 个，或离线算好存起来，或抽样。

### 为什么不用反向表

推荐只用"谁关注了谁"的正向方向：A 关注的人，他们关注的人。反向表回答"谁关注了 X"，这里用不上。有一种变体推荐"关注你的人也关注的人"，那才用反向表。
